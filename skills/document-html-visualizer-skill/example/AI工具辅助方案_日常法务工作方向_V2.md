# 康哲药业法务部AI辅助体系全生命周期建设方案 V2.0

> **编制：** 小龙虾（AI数字员工）
> **日期：** 2026年7月6日
> **版本：** V2.0
> **状态：** 内部规划使用
> **V2 相对 V1 的定位：** V1 解决了"从0到1把AI用起来"的问题；V2 解决"把AI用对、用稳、用出可证明的价值"的问题。

## 零、V2 相对 V1 的六项核心升级

| 升级项 | V1 现状 | V2 改动 | 目的 |
|-------|--------|--------|------|
| 1. 价值锚点 | 从"通用合同审核"起步 | 把会议赞助合规预审、IIT合规预审这两个最高频且最高风险的专项前置为首个高价值场景 | 让投入落在ROI与风险都最高的地方 |
| 2. 质量机制 | 只有知识自动积累的闭环 | 补齐"质量闭环"，形成知识、质量、风险三重闭环 | 让系统越用越准，且更新后不退化 |
| 3. AI治理与安全 | 基本空白 | 新增治理与安全底座：反幻觉硬约束、分级人机协同、数据保密分级、全程留痕、轻量治理小组 | 让一个风控部门敢把AI用在敏感事务上 |
| 4. 度量 | "效率提升50%"等断言，无测量设计 | 先建基线，再定KPI（效率、质量、风险、采纳四类，区分先行与滞后指标） | 用数据向管理层证明价值 |
| 5. 场景覆盖 | 合同、咨询、知识管理三大场景 | 补上合规专项（会议赞助、IIT、推广材料、集采招投标）与风险争议处置（期限监控、案件台账、文书辅助、劳动争议、协查打假、不良反应时限） | 覆盖法务真正的全貌，而非只覆盖事务性主干 |
| 6. 采纳与主体 | 依赖6人每周额外转发Q&A；深西康单体视角 | 把知识采集嵌入工作流（就地捕获、一键确认）；知识库支持多主体标签，为4家子公司扩展预留接口 | 降低采纳阻力，支撑集团化推广 |

## 一、总体建设框架

### 1.1 三层架构（V2 新增"治理与安全底座"）

V1 是"能力层加场景层"的两层结构。V2 在其下补一层地基，形成三层：

1. **底座层（治理与安全）：** 反幻觉输出纪律、分级人机协同、数据保密分级、审计留痕、法务AI工作小组。这一层决定AI能不能被信任地用在法律事务上。
2. **能力层（知识与技能）：** 各类知识库 + 各类Skill。这一层决定AI能做多少事、做得多准。
3. **场景层（业务落地）：** 合同审核、智能咨询、合规专项、风险与争议处置、知识管理。这一层决定AI在日常工作中真正解决了什么。

### 1.2 建设原则（在 V1 四条上增加两条）

V1 四原则继续保留：急用先行、知识先行、渐进演化、人机协同。V2 增加两条，作为一切设计的前提：

1. **可核验优先。** 宁可AI慢一点、少答一点，也要保证每一条结论可追溯到来源、可被法务快速核验。可靠比聪明更重要。
2. **度量驱动。** 任何场景上线前先测基线，上线后用KPI说话。没有基线的效率提升不算数。

### 1.3 价值锚点重排：先啃最硬也最值钱的骨头

法务运营的通行判断是：最该优先自动化的，是"高频、低单件战略价值"的工作。对深西康而言，量最大的两块是会议赞助（约6,000/年）与IIT合同（约2,500/年）。这两块同时又是国家市场监管总局《药械企业防范商业贿赂风险合规指引》明确点名的高风险场景（学术拜访/学术会议、临床研究）。因此它们是"高频、高风险、高标准化"三高交汇点，自动化预审在这里的边际价值最高。

**V2 决定：** 第一个跑通的高价值场景不是通用合同审核，而是**会议赞助合规预审**；紧随其后是**IIT合规预审**。通用合同审核能力同期建设，但不再是唯一起点。

### 1.4 整体时间轴（Track 升级）

总目标不变：2026年底前完成知识库基础建设并跑通至少一个高价值场景，2027年底实现全面覆盖。V2 在 V1 四条 Track 上增加一条 Track E（治理与度量），并把两个合规专项前置。

| Track | 定位 | 2026年7至9月 | 2026年10至12月 | 2027年 |
|-------|------|-------------|---------------|--------|
| Track A：知识库 | 全程持续积累 | 收集机制建立 + 风控标准与会议赞助/IIT规则入库 | 规模成型 + 知识闭环 | 多主体扩展 |
| Track B：合同与合规专项 | 全程 | 会议赞助合规预审跑通 + 合同审核Skill实测 | 合同审核全链路 + IIT合规预审 | 推广材料、集采招投标专项 |
| Track C：智能咨询 | 晚于知识库启动 | A类试点 | A类常态化 | B类上线（对齐SAMR九大场景） |
| Track D：系统集成 | 按需插入 | 钉钉API对接（立项/采购状态核查） | 督促与期限监控Skill上线 | 管理驾驶舱 |
| Track E：治理与度量（V2新增） | 全程 | 基线测量 + 治理小组组建 + 输出纪律与留痕上线 | KPI看板v1 + 质量闭环运转 | 风险闭环成熟 + 定期审计 |

**2026年底必须完成的硬性目标（升级版）：**

1. 深西康法务知识库基础版建立完成。
2. 至少一个高价值场景（会议赞助合规预审）全流程跑通并实测。
3. 治理与安全底座上线：输出纪律、分级复核、数据保密分级、审计留痕四件套可用。
4. 基线测量完成，KPI看板v1可用。

## 二、AI治理与安全底座（V2 新增，优先级最高）

这一节是 V2 与 V1 最大的差别，也是一个风控部门最该主导的部分。行业证据是清楚的：即便用了检索增强（RAG）的专业法律AI工具，幻觉率仍在17%到33%之间，通用大模型在法律问题上更高。所以我们不寄希望于"模型足够聪明就不会错"，而是把"可核验、可控制、可追溯"做进机制。

### 2.1 反幻觉输出纪律（对AI每次作答的硬约束）

1. **先检索、后作答。** 涉及法规、案例、风控标准的结论，必须基于检索到的知识库内容生成，不得凭记忆作答。
2. **无依据不下结论。** 检索不到充分依据时，AI必须明确说"当前依据不足，建议人工确认"，不得编造。
3. **每条结论附来源与置信度。** 引用哪条法规、哪条风控标准、哪条历史Q&A，必须可点回原文；同时标注高/中/低置信度。
4. **禁止编造法规条文与案例。** 这是红线。法务引用一条不存在的法规是严重事故。
5. **三态标注。** 每个要点标注为"有明确依据 / 需人工核实 / 无法回答"三态之一，让法务一眼看出哪里可以信、哪里必须自己判断。

### 2.2 分级人机协同（按风险决定自动化程度）

不是所有事务都需要同样强度的人工介入。V2 按风险给出四档自动化，越高风险，人工把关越强。

| 风险档 | 典型场景 | AI自动化程度 | 人工介入方式 |
|-------|---------|-------------|-------------|
| 低风险 | A类流程/制度咨询（如用印审批找谁） | AI直接生成指引草稿 | 法务抽检，留痕 |
| 中风险 | 标准合同预审、会议赞助合规预审 | AI出结构化预审报告 + 风险标注 | 法务逐份复核后放行 |
| 高风险 | B类合规判断、IIT合规、对外正式文书 | AI只出分析框架 + 参考结论 + 依据 | 法务必须复核并签署，过审批门（approval gate）后方可发出 |
| 禁止自动放行 | 最终对外结论、盖章、承诺性文件 | AI辅助起草，绝不自动对外 | 法务终审并对结果负责 |

配套的三个治理要点：定义清楚每个环节的人工复核点与责任人；给法务保留随时推翻AI结论的权利（override）；设定清晰的升级路径（AI拿不准或出现冲突时，升级给谁）。

### 2.3 数据安全与保密分级

法律咨询、合同、风控标准是公司最敏感的资产之一。V2 对进入AI系统的数据分级管理。

| 数据级别 | 例子 | 存储与权限 | 脱敏 | 留痕 |
|---------|------|-----------|------|------|
| 公开级 | 已公布法规、公开裁判文书 | 可入通用知识库 | 无需 | 常规 |
| 内部级 | 集团风控标准、制度流程、A类FAQ | 限法务部访问，最小权限 | 无需 | 全程 |
| 敏感级 | 具体合同、当事人信息、争议细节、B类具体咨询 | 严格限权、脱敏后入库、原件单独受控 | 入库前脱敏（隐去主体、金额等） | 全程且加强 |
| 禁入级 | 个人身份证号、银行账号、未脱敏的患者数据 | 不进入AI系统 | 不适用 | 不适用 |

三条基本要求：进入AI系统的敏感数据不外传、不用于训练第三方模型；明确知识库的物理存储位置与访问权限清单；涉及个人信息的处理遵循个人信息保护法（PIPL）。ABA 第512号正式意见对生成式AI的保密要求可作参照：使用者要清楚AI如何处理数据，并提供充分保障。

### 2.4 可审计与全程留痕

风控部门必须能回答"这个结论是谁、基于什么、什么时候给出的"。因此每一份AI产出都记录一条可回溯日志：输入内容、检索到的依据、模型版本、生成时间、复核人、审批状态。这既是质量闭环的原料，也是万一被追问时的证据。

### 2.5 轻量治理结构：法务AI工作小组

V1 把几乎所有产出压在AI加李文思一人（30%精力）身上，既是瓶颈也是关键人风险。V2 设一个不增编制的轻量小组，把"决策、验收、风险升级"从一个人身上解耦：

| 角色 | 由谁担任 | 职责 |
|------|---------|------|
| 组长 | 法务总监 | 方向决策、对外协调、风险最终升级 |
| 知识与产品Owner | 李文思 | 知识库质量、Skill验收、基线与KPI维护 |
| 业务联络人 | 各业务线1名法务同事轮值 | 反馈一线问题、推动本条线知识贡献 |
| IT接口人 | IT部门1人 | 钉钉API、数据安全支持 |

治理的最低标准：一个人或这个小组能够基于书面标准，决定停止或批准某个AI用例，而不是凭个人临时判断。

## 三、三重闭环体系（V2 核心机制）

V1 只有一条闭环（知识自动积累）。V2 把它扩成三条相互咬合的闭环，共同实现"越用越准、越用越安全、越用越前置"。

| 闭环 | 触发 | 核心流程 | 产出 | 关键指标 |
|------|------|---------|------|---------|
| 知识闭环 | 每次咨询/审核完成 | 就地捕获Q&A，AI提取结构化字段，去重与冲突检测，入库复用 | 自生长的知识库 | 自动入库覆盖率、重复率、冲突数 |
| 质量闭环（V2新增） | 每份AI产出被法务修改 | 捕获修改差异（改了什么、为什么），沉淀为纠错案例，纳入回归测试集，反哺规则与提示词 | 越来越准的Skill | AI初稿被修改幅度、返工率、回归通过率、幻觉率 |
| 风险闭环 | 高频风险点被识别 | 趋势监控，预警，把常见风险固化为审核规则/模板，前置到下一次审核 | 主动预警与更优模板 | 风险命中率、预警及时率、同类风险复发率 |

### 3.1 知识闭环

在 V1 基础上，把采集从"同事额外转发"改为"就地捕获"：AI在咨询私信流或审核流里直接抓取问答，法务只需一键确认或补一句标签。这样知识贡献不再是额外负担，而是顺手完成。入库前做去重与冲突检测（同一问题出现不同结论时，标注供法务复核）。

### 3.2 质量闭环（最重要的新增）

核心思想：把法务对AI初稿的每一次修改，都变成系统的改进信号。

1. **捕获差异。** AI给出初稿，法务修改后定稿，系统记录"改了哪里、往哪个方向改"。
2. **沉淀纠错案例。** 把典型修改整理成"错误模式—正确做法"的案例，回填知识库。
3. **回归测试集（golden set）。** 从真实业务里挑选一批有标准答案的代表性问题作为固定测试集（起步30到50条，覆盖：有明确答案的、需多文档综合的、有歧义的、以及"应回答无法确定"的四类），每次知识库或Skill更新后跑一遍，防止改好一处、退化一处。
4. **质量指标。** 参照检索增强系统的通用度量：答案相关性、忠实度（结论是否严格来自检索到的依据）、检索精确率与召回率，外加引用覆盖率与幻觉率。用"上线前离线回归 + 上线后抽样在线监控"两条腿走路。用AI做初步打分可以，但要用人工核验过的标准集去校准，因为AI评审本身有偏好长答案等系统性偏差。

对一个做过强化学习的人来说，这一条最容易理解：法务的每次修改就是奖励信号，golden set就是防止过拟合和性能退化的验证集。

### 3.3 风险闭环

监控各类问题的咨询热度与合同高频风险点，异常上升时预警；新法规出台时自动评估影响并推送相关业务线；把反复出现的风险固化为审核规则和合同模板，前置到下一次审核，从"被动响应"转向"主动防范"。

## 四、度量体系：先建基线，用数据说话

法务运营的第一课是：你无法测量你看不见的东西。V2 要求任何场景上线前先建基线。

### 4.1 基线测量（第一阶段前2周）

在AI介入前，先记录现状：各类事项的处理时长、从发起到办结的周转时间、返工轮次、当前积压量、月度事项量分布。这份基线是日后一切"提升了多少"的对照系。

### 4.2 KPI 体系（四类，区分先行与滞后指标）

| 类别 | 指标 | 类型 | 说明 |
|------|------|------|------|
| 效率 | 合同周转时间（办结时间减发起时间，按合同类型分段） | 滞后 | 法务是否成为业务瓶颈 |
| 效率 | 咨询平均响应时长、单份审核平均耗时 | 滞后 | 直接反映减负 |
| 质量 | AI初稿被法务修改幅度、返工率 | 滞后 | 检验"快"是否也"对" |
| 质量 | 抽检准确率、幻觉率、回归测试通过率 | 先行 | 提前发现质量退化 |
| 风险 | 高频风险命中率、法规预警及时率、合规专项覆盖率 | 先行 | 提前发现合规隐患 |
| 采纳 | 场景覆盖率、法务使用率、知识库健康度（总量/新增/质量分/老化率） | 先行 | 系统是否真被用起来 |

一个重要提醒：质量比吞吐更难测，务必跟踪结果类指标（被修改幅度、返工、争议、合规发现），用它们验证效率提升不是以牺牲质量为代价。

### 4.3 度量节奏

周：知识库健康度与质量抽检。月：效率与风险KPI、AI辅助价值报告。季：治理小组复盘，回归测试集更新，老旧知识复核。

## 五、场景建设

### 5.1 合同审核（沿用 V1 五环节，补两块）

V1 的立项合规核查、条款审核、多版本比对、定稿与盖章比对、履约督促五环节全部保留。V2 补充：

1. **模板与条款库。** 建立标准合同模板与可选条款库（含各风险级别的备选条款）。让约80%的标准合同走"模板 + AI预审 + 快速通道"，法务把精力集中到非标合同。
2. **合同后义务管理。** 履约督促不止于催归档，而是从签署后的合同里提取关键义务（续约、到期、付款节点、排他期、赔偿上限）并到期预警，覆盖合同全生命周期。

### 5.2 智能咨询（A/B类，B类显式对齐SAMR）

A类（流程/制度）与B类（合规判断/合同内容）保留。V2 的关键升级：把B类合规判断显式对齐国家市场监管总局九大高风险场景，形成"场景到红黄绿灯到依据"的结构化规则库。指引把商业活动分为禁止、限制、建议、提倡四类，知识库据此建立分类判断，让B类咨询有稳定、可核验的判断骨架。

### 5.3 合规专项（V2 新增，价值最高）

| 专项 | 年量级 | 对应SAMR高风险场景 | AI预审重点 |
|------|-------|------------------|-----------|
| 会议赞助合规预审 | 约6,000 | 学术拜访/学术会议 | 会议真实性、讲者费公允性、行程与发票一致、是否与销量挂钩 |
| IIT合规预审 | 约2,500 | 临床研究 | 利益冲突、费用合理性、是否借研究变相输送利益、伦理与数据合规、是否经第三方操纵研究 |
| 推广材料合规审查 | 约960 | 学术推广 | 适应症一致（防止适应症外推广）、疗效表述、绝对化用语、广告法与药品广告审查办法 |
| 集采招投标合规 | 按需 | 招投标 | 围标串标风险、投标文件合规 |

同时提示一个监管动向：反不正当竞争法修订草案拟处罚受贿方、提高罚款上限，并可对法定代表人及直接责任人个人处罚。这意味着合规不再只是公司层面的风险，也是个人层面的风险，专项预审的价值更高。

### 5.4 风险与争议处置（V2 新增，法务的另一半）

汇报版列了约300个/年风险事件，V1 却几乎没为它们建AI能力。V2 补上，重点是"有硬期限、易遗漏"的工作，这恰恰最适合AI做期限监控。

1. **期限监控。** 诉讼时效、举证期限、协查配合时限、不良反应报告法定时限等，统一台账加自动提醒，杜绝因超负荷而错过期限。
2. **案件与争议台账。** 案件状态、关键节点、外部律师、进展一览。
3. **文书辅助。** 常见文书（如律师函、答复函）基于模板辅助起草，法务终审。
4. **劳动争议专项。** 支撑4家子公司与集团人力的高频劳动争议。
5. **协查、打假统筹。** 证据固定与流程跟踪。

### 5.5 知识管理（沿用 V1，并入质量闭环）

V1 的知识自动积累、去重、质量评分、周更报告保留，并入上文的质量闭环，增加纠错案例与回归测试集两项产出。

## 六、分阶段实施（四阶段，升级版）

### 第一阶段（2026年7至9月）：底座 + 基线 + 第一个高价值场景

**目标：** 治理与安全底座上线；基线测量完成；会议赞助合规预审跑通；知识与质量双闭环启动。

**核心交付：** 会议赞助合规预审产出首批预审报告并实测；输出纪律、分级复核、数据保密分级、审计留痕四件套可用；基线数据成型。

**验收标准（含质量与安全）：**

1. 治理小组组建完成，书面职责与升级路径明确。
2. 输出纪律生效：AI结论均附来源与三态标注，抽检无编造法规/案例。
3. 数据保密分级落地，敏感数据入库前脱敏。
4. 会议赞助合规预审实测≥20份，法务满意度≥80%，且预审报告100%留痕。
5. 基线测量完成，覆盖会议赞助、合同审核、咨询三类的现状时长与量。
6. 质量闭环启动：golden set建立（≥30条），首轮回归测试跑通。

### 第二阶段（2026年10至12月）：合同全链路 + A类常态化 + IIT专项 + 知识库基础版

**目标：** 合同审核五环节全部AI化；A类咨询常态化；IIT合规预审上线；知识库基础版建立；KPI看板v1可用。

**验收标准：**

1. 合同审核五环节全部上线并实测，含模板快速通道。
2. A类咨询AI辅助连续4周覆盖率≥80%。
3. IIT合规预审实测≥10次，法务评价"有参考价值"≥80%。
4. 知识库基础版建立：风控标准 + 会议赞助/IIT规则 + A类流程 + B类FAQ，可检索可用。
5. KPI看板v1上线，覆盖效率、质量、采纳三类，数据来自真实运行。
6. 质量闭环运转：回归通过率与幻觉率纳入月报。

### 第三阶段（2027年上半年）：B类咨询 + 争议期限监控 + 合同后义务管理

**目标：** B类咨询AI辅助上线（对齐SAMR）；争议与风险处置的期限监控上线；合同后义务管理上线；质量闭环成熟。

**验收标准：**

1. B类咨询AI辅助运行≥10次，满意度≥80%，均附依据与置信度。
2. 期限监控覆盖诉讼时效、举证期限、协查与不良反应时限，异常提醒无遗漏。
3. 合同后义务提取与到期预警覆盖所有在途合同。
4. golden set扩充至≥80条，回归测试纳入每次上线前必过环节。

### 第四阶段（2027年下半年）：风险预警主动化 + 多主体扩展 + 管理驾驶舱

**目标：** 风险预警从被动转主动；知识库扩展到子公司主体；管理驾驶舱上线。

**验收标准：**

1. 月度风险趋势报告连续3个月稳定产出，法规预警每月≥1次。
2. 知识库多主体标签落地，至少1家子公司完成知识接入试点。
3. 管理驾驶舱覆盖咨询、合同、知识库、风险四维度，月度AI辅助价值报告连续6个月稳定运行。

## 十一、风险与对策（升级）

| 风险 | 概率 | 影响 | 对策 |
|------|-----|-----|------|
| AI编造法规或案例（幻觉） | 高 | 高 | 反幻觉输出纪律 + 三态标注 + 高风险强制法务复核；把"可核验"做进机制，不依赖模型自觉 |
| 敏感数据泄露或误用 | 中 | 高 | 数据保密分级 + 脱敏 + 最小权限 + 不用于训练 + 全程留痕 |
| 法规过时导致误判 | 中 | 高 | 法规版本库带生效日期与废止管理，定期更新 |
| 过度依赖AI、法务判断力退化 | 中 | 中 | 坚持法务终审对结果负责，AI仅辅助；高风险场景绝不自动放行 |
| 同事不配合知识收集 | 中 | 高 | 就地捕获降低负担 + 月度知识贡献榜激励 + 先从积极同事试点 |
| 钉钉API权限受阻 | 中 | 中 | 提前与IT沟通，确认可行再排期 |
| 质量初期不稳且更新后退化 | 高 | 中 | golden set回归测试 + 阶段性合理目标，不追求一步到位 |

## 结语

V1 让法务部把AI用了起来，这一步已经很有价值。V2 想解决的是下一个问题：在一个监管高压、个人也可能被追责的环境里，如何把AI用得既快又稳，并且能拿出数据证明它到底带来了什么。三重闭环让系统越用越准，治理底座让一个风控部门敢把AI用在最敏感的事务上，价值锚点让投入落在最值钱的地方，度量体系让一切可被证明。方案仍以"可落地、可验收"为标准，各阶段验收含质量与安全指标，后续按实际执行动态调整。
